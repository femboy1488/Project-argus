# Роли нод (план от 2026-11-01, статус на 0.3.3)

> **Статус 0.3.3 (нода):** единый протокол ролей (ниже), Голос (whisper-server) и Библиотека (kiwix-serve) в APK, телеметрия температуры/батареи.
>
> **Статус:** в 0.3.2 сделаны прогрев, тест скорости нод, деление слоёв по скорости, роли «Авто / Часть модели / Свободна» и экспериментальная роль **Помощник** (включается переключателем «Роли» в Cluster). Поиск, Голос и Библиотека — ещё план.

Сейчас все ноды работают как одна модель (pipeline по слоям): каждый токен проходит GPU → нода 1 → нода 2 по очереди. Лишние ноды добавляют память, но не скорость.

Режим «Роли»: каждое устройство одновременно делает свою работу, а Argus на ПК раздаёт задачи.

## Роли
| Роль | Что делает | Движок на ноде | Порт (adb forward) |
|---|---|---|---|
| Часть модели | слои главной модели (как сейчас) | rpc-server | 50052 (ПК 50052+) — ✅ |
| Помощник | маленькая модель 0.6–4B: сводки, названия чатов, перевод, подзадачи агента | llama-server (arm64) | 50062 (ПК 50162+) — ✅ 0.3.2, эксперимент |
| Поиск | эмбеддинги для поиска по файлам (RAG) | llama-server --embedding | 50060 |
| Голос | распознавание речи | whisper.cpp server | 50061 |
| Библиотека | офлайн-Википедия | kiwix-serve | 50063 |
| Свободна | ничего, не греется | — | — — ✅ 0.3.2 |

## Как работает
1. Автотест каждой ноды при подключении: скорость (tok/s на эталонном слое), RAM, температура.
2. Авто-раскладка: главная модель берёт GPU + минимум самых быстрых нод, чтобы влезть; остальные получают роли по RAM/скорости. Пользователь может переопределить роль вручную.
3. Модели для ролей качаются на ПК и передаются на ноду (adb push по USB или HTTP :50055 по Wi‑Fi), хранятся в памяти приложения ноды.
4. Нода-приложение получает команду «роль X, модель Y» и запускает нужный движок вместо/рядом с rpc-server.
5. На ПК очередь задач: тип задачи → роль → нода. Если нода пропала — задача уходит на CPU ПК или главную модель.
6. В чате видно, кто что сделал (Note10+ нашёл 3 фрагмента, A52 распознал голос).

## Пример (железо автора)
- GTX 960 + быстрый телефон: Qwen3 4B — чат ~14 tok/s.
- Note10+ (12 ГБ): Поиск + Помощник (Qwen3 1.7B).
- A52: Голос (whisper small).

## Ограничения
- Один ответ быстрее не станет; быстрее и богаче становится всё вместе.
- Нагрев/батарея телефонов, RAM каждой ноды.

## Протокол ролей ноды (Android, с 0.3.3, versionCode 7)

rpc-server («Часть модели») работает всегда; остальные роли запускаются **рядом** с ним и не исключают друг друга.
rpc-server берёт большие ядра (`-t` = big+prime, `force_threads` — переопределение), роли Помощник и Голос по умолчанию —
малые ядра (`-t` = число малых ядер, минимум 2); если работает `toybox taskset`, процесс роли прикрепляется к малым ядрам
(best effort; если потоков больше, чем малых ядер, — без привязки).

### Команды по USB (adb)
`adb shell am start-foreground-service -n com.harkcluster.node/.RpcService <extras>`

| Extra | Значение |
|---|---|
| `--es role rpc\|helper\|voice\|library\|idle` | запустить роль (можно через запятую). `rpc` — ничего не делает (rpc-server и так идёт), `idle` — остановить все роли кроме rpc |
| `--es role_stop helper\|voice\|library\|all` | остановить роль(и) и **забыть** назначение (обрабатывается до `role`) |
| `--es helper_model <file.gguf> --es helper_url <url> [--el helper_size N] [--ei helper_threads N]` | Помощник (llama-server). Без `role` тоже работает (как в 0.3.2) |
| `--ez helper_stop true` | устаревшее = `role_stop helper` |
| `--es voice_model <file.bin> --es voice_url <url> [--el voice_size N] [--ei voice_threads N]` | Голос (whisper-server); `voice_url` обычно `http://127.0.0.1:50055/helper/<file>` (adb reverse) |
| `--es zim <file.zim>` | Библиотека: имя файла в `filesDir/zim` (или абсолютный путь). Без `zim` — последний назначенный, иначе самый новый .zim |
| `--ez wifi true\|false`, `--ei port`, `--ei force_threads` | как раньше |
| action `com.harkcluster.node.STOP` | остановить узел; назначения ролей **сохраняются** и поднимутся при следующем старте |

Назначения хранятся в SharedPreferences `node` (`role_helper`, `role_voice`, `role_library`) и перезапускаются после
перезапуска сервиса (START_STICKY, обновление APK, «Запустить узел»). Любая остановка роли (`role_stop`, `role=idle`,
`helper_stop`, `"<роль>": false` в ответе на маяк) работает независимо от того, откуда роль была назначена (в 0.3.2
`"helper": false` останавливал только помощника, назначенного по Wi-Fi — исправлено).

### Порты
| Роль | Движок | Порт на телефоне | Адрес (USB / Wi-Fi) |

### Состояние: USB (dumpsys)
`adb shell dumpsys activity service com.harkcluster.node/.RpcService` печатает строки:
- `argus-helper state=… pct=… model=… error=…` (как в 0.3.2)
- `argus-status {json}` — **одна строка JSON** (новое в 0.3.3)
- `argus-rpc …`, `argus-bench …` (как раньше)

```json
{"argus":"status","v":1,"vn":"0.3.3","vc":7,
 "temp_c":38.5,"battery_temp_c":34.0,"cpu_temp_c":38.5,"thermal_status":0,"throttled":false,
 "battery_pct":81,"charging":true,"usb_net_ip":"192.168.42.129","wifi_ip":"192.168.1.23",
 "rpc":{"state":"linked","port":50052,"threads":4,"big_cores":4,"variant":"dotprod","mode":"usb"},
 "roles":{"helper":{"state":"ready","pct":100,"port":50062,"threads":4,"model":"Qwen3-1.7B-Q4_K_M.gguf"},
          "voice":{"state":"idle","port":50061,"pct":0,"threads":0},
          "library":{"state":"ready","port":50063,"zim":"wikipedia_ru_all_mini.zim"}}}
```
Состояния ролей: `idle | downloading | starting | ready | error` (+ `error`, `pct`; у library — `import_pct` пока копируется .zim).
Необязательные поля (`temp_c`, `cpu_temp_c`, `battery_pct`, `usb_net_ip`, `wifi_ip`) отсутствуют, если значение неизвестно.

- `temp_c` = max(температура батареи `EXTRA_TEMPERATURE/10`, максимум `/sys/class/thermal/thermal_zone*/temp`; зоны часто закрыты SELinux → только батарея).
- `throttled` = `PowerManager.currentThermalStatus ≥ THERMAL_STATUS_MODERATE` (Android 10+, иначе false); `thermal_status` — сырое значение 0…6.
- `usb_net_ip` — IPv4 интерфейса `rndis*`/`ncm*`/`usb*` (USB-модем).

### Состояние: Wi-Fi (маяк UDP :50053)
В JSON маяка добавлены те же поля телеметрии (`temp_c`, `battery_temp_c`, `cpu_temp_c`, `thermal_status`, `throttled`,
`battery_pct`, `charging`, `usb_net_ip`) и `"roles": {helper, voice, library}`. Старое поле `"helper"` осталось.
Неизвестные ключи ПК игнорирует.

Ответ ПК на маяк (`{"argus":"host",…}`) может содержать: `"helper": {file,path,size,threads} | false`,
`"voice": {file,path,size,threads} | false`, `"library": {"zim":…} | false`; отсутствие ключа — без изменений.

### Библиотека на телефоне
Кнопка «Выбрать .zim» (системный выбор файла, SAF) копирует файл в `filesDir/zim` с прогрессом. Если роль Библиотека
уже работает, она переключается на новый файл. ПК включает роль `--es role library [--es zim <имя>]`.

### Подсказка о нагреве
Если телефон заряжается и `temp_c ≥ 40` или `throttled`, приложение показывает: «Если заряжается и греется — ограничь
заряд до 85% в настройках батареи».
